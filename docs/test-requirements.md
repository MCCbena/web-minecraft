# Web Minecraft — テスト要件定義 (Test Requirements)

> 前提: `docs/requirements.md` / `docs/design.md`
> テストフレームワーク: **Vitest**（ユニット）/ **Playwright**（E2E・UI）

---

## 1. テスト方針 (Strategy)

- 純粋ロジック（地形生成、ワールド、物理、レッドストーン）は**ユニットテスト**で網羅。
- レンダリング・入力・UI は**E2E（Playwright）**+ **スクリーンショット**で確認。
- 全テストは CI 的に `npm test` で一発実行可能。

## 2. ユニットテスト要件 (Unit Test Requirements)

### 2.1 地形生成 (terrain.test.ts)
| ID | 要件 | 期待 |
|----|------|------|
| T-01 | 高さmap の範囲 | 全 (x,z) で 0 < h < 64 |
| T-02 | ベッドロック | y=0..2 が Bedrock |
| T-03 | 決定論 | 同一シードで 2 回生成し、全ブロック一致 |
| T-04 | 群系 | 草原/砂漠/水辺のいずれかが存在 |
| T-05 | 木 | 原木 + 葉が少なくとも 1 本生成 |
| T-06 | 水 | 水面高さ以下の低地が Water |
| T-07 | 洞窟 | 3D Noise で AIR の空洞が生成 |

### 2.2 ワールド (world.test.ts)
| ID | 要件 | 期待 |
|----|------|------|
| W-01 | set/get | 設定したブロックが読み出せる |
| W-02 | 境界外 | 境界外 get は AIR、set は無視 |
| W-03 | インデックス | 世界座標 ↔ チャンクローカル座標の変換が正しい |
| W-04 | 破壊不可 | Bedrock は set(Air) で無効（またはフラグ） |

### 2.3 物理 (physics.test.ts)
| ID | 要件 | 期待 |
|----|------|------|
| P-01 | 重力 | 浮遊時 vy が毎 tick 減少 |
| P-02 | 着地 | 地面に到達で onGround=true、vy=0 |
| P-03 | ジャンプ | 地上でスペース → vy > 0 |
| P-04 | 衝突 | 壁に衝突で x 移動が止まる |
| P-05 | フライト | フライト中は重力無効、スペースで上昇 |

### 2.4 レッドストーン伝播 (redstone-propagation.test.ts)
| ID | 要件 | 期待 |
|----|------|------|
| R-01 | 減衰 | 強い電源(15)から dust が 14,13,...,1 で 15 ブロックまで伝播 |
| R-02 | 範囲制限 | 16 ブロック目は電力 0 |
| R-03 | 強い電源 | レッドストーンブロックが隣接 dust を 15 で駆動 |
| R-04 | 火把反転 | 支持ブロック無電力→火把 ON(15)、有電力→火把 OFF(0) |
| R-05 | 分岐 | 電源から分岐した dust が両方駆動 |

### 2.5 レッドストーンコンポーネント (redstone-components.test.ts)
| ID | 要件 | 期待 |
|----|------|------|
| C-01 | NOT ゲート | 火把 1 段で入力を反転 |
| C-02 | リピータ遅延 | 入力 ON で delay tick 後に出力 ON、OFF でも delay 後に OFF |
| C-03 | リピータブースト | 入力 1 でも出力 15 |
| C-04 | コンパレータ減算 | input=10, side=4 → out=6 |
| C-05 | コンパレータ比較 | input > side → out=input、それ以外 0 |
| C-06 | オブザーバ | 観察ブロック変化で 1 tick パルス(15)出力 |
| C-07 | ピストン伸長 | 電力で伸長先ブロックが 1 ブロック移動 |
| C-08 | ピストン制限 | 12 ブロック超 or 不可動ブロックで伸長しない |
| C-09 | 粘着ピストン | 縮退時に保持ブロックを引き戻す |
| C-10 | TNT 爆発 | 着火後 fuse 経過後、半径内の破壊可能ブロックが AIR |
| C-11 | TNT 連鎖 | 爆発範囲内の TNT が連鎖着火 |
| C-12 | 日中検知器 | 昼→15、夜→0、逆転モードで反転 |
| C-13 | 灯籠 | 電力で点灯、無電力で消灯 |
| C-14 | レバー/ボタン | ON/押下で 15、ボタンは 10 秒後に解放 |

### 2.6 回路再現 (redstone-circuits.test.ts)
| ID | 要件 | 期待 |
|----|------|------|
| K-01 | AND ゲート | 2 入力火把回路で両方 ON のみ出力 |
| K-02 | OR ゲート | いずれか ON で出力 |
| K-03 | クロック | 火把+リピータループで周期的パルス |
| K-04 | ピストンドア | 電力でブロックが移動し道が開く |

## 3. E2E / UI テスト要件 (Playwright)

| ID | 要件 | 期待 |
|----|------|------|
| E-01 | 開始画面 | タイトル + 操作説明（日本語）+「クリックしてプレイ」表示 |
| E-02 | プレイ開始 | クリックで Pointer Lock、ワールド表示 |
| E-03 | HUD | クロスヘア、ホットバー、座標、FPS が表示 |
| E-04 | ブロック設置 | 右クリックでブロックが置かれる（スクリーンショット比較） |
| E-05 | ブロック破壊 | 左クリックでブロックが消える |
| E-06 | ホットバー切替 | 数字キー/ホイールで選択が変わる |
| E-07 | 昼夜 | 時間が経過で空の色が変化（スクリーンショット） |
| E-08 | レッドストーン | レバー ON で灯籠が点灯（スクリーンショット） |

## 4. 品質ゲート (Quality Gates)

- `npm run build` 成功（TypeScript strict、エラーゼロ）
- `npm test` 全合格
- Playwright E2E 全合格
- スクリーンショットで UI 品質を確認（HUD 配置、文字化けなし、日本語表示）

## 5. 実行コマンド

```powershell
npm install
npm run build      # ビルド検証
npm test           # Vitest ユニットテスト
npm run test:e2e   # Playwright E2E
npm run dev        # dev server（バックグラウンド起動）
```
